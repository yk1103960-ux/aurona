# Guided variation creation and duplication

Implemented on `codex/phase-2a-admin`. Static checks only; database/browser acceptance remains REQUIRED. No production changes, new migrations, schema, API, checkout or shipping changes in this update.

## Client workflow

Open Products → a product → Manage Variations → **Add Variation · step by step**.

1. **Images:** select images, describe them and choose a primary image. Images are optional. New selections stay local until the SKU saves; JPG/PNG/WebP/GIF/AVIF, at most 12 selected images per batch and 8 MB per image.
2. **Product options:** the shared Product Options / Attributes box includes Wattage, Size, Body / Housing Colour, Pack Size, Output Colour and Add Option for custom attributes such as Shape, Oscillation, Tank Capacity or Reflector Colour. Templates remain visible after adding the first option. Enter actual comma-separated values and select which values to include in generation.
3. **SKU & values:** choose the new SKU, optional barcode/name and each option value. Add SKU-specific specifications. Saved SKU codes remain read-only for order/image integrity; labels and options can change.
4. **Prices & MOQ:** customer, retailer and distributor prices, MRP, role MOQs and pieces per pack.
5. **Stock & dimensions:** stock quantity, alert threshold, unit/package weights and dimensions.
6. **Review & save:** inspect the summary, choose inactive/available and save all outstanding changes in this family.

Inside the wizard, **Save Options** prepares the shared option draft and **Save & Generate Variations** prepares missing inactive combinations. These actions do not prematurely persist the autogenerated SKU. Final Review & Save writes options and variant details through the existing transactional v3 routine, then attaches selected images. Outside the wizard, the existing Save Options action continues saving the matrix; explanatory text distinguishes the behavior.

**Duplicate Variation** is available on each variant card and in a saved variation’s editor. It opens the copy immediately. Names/options, all role prices/MOQs, measurements and image references are copied. The copy receives a unique draft SKU and new image-association IDs. Stock is zero, barcode blank, and availability inactive. Editing copied attributes cannot mutate the source. No existing file or SKU is deleted or overwritten.

Change the duplicate’s SKU/values and review prices and photos before activating. Two active SKUs with the same selected option combination are blocked. Server-side global SKU validation remains authoritative.

## Persistence and recovery

- Uses the existing Supabase media bucket, product_images table and primary-image routine. Copies share stored bytes but have independent associations; existing safe file-retention behavior remains.
- Uses the single controlled shared option draft. Opening/closing the modal or switching wizard/pricing steps does not reset entered options.
- Final save still saves the family matrix, not just the currently displayed row. UI states this explicitly.
- Pending selections are temporary, not durable drafts. “Close · keep edits” retains them while this workspace stays mounted. Leaving/reloading warns; it does not promise browser-restart recovery.
- Saved-image controls are scoped to this SKU and explicitly state that their changes apply immediately.
- A failed photo upload/association/primary operation reports that variant details are already saved. Retrying reuses successful uploaded URLs and stable association IDs, and skips completed stages. Upload and database metadata are not a single distributed transaction; an ambiguous failed storage response can leave an unassociated file for later cleanup. No automatic deletion is performed.
- Generation preserves existing rows and creates only missing combinations, as before. The initial manually opened draft is not silently repurposed or deleted.
